    1. Perintah Deploy di Cloud VPS IDCloudHost (Ubuntu / Docker)
    
            
          
    
          
    
            Gunakan kredit IDCloudHost Anda pada menu Cloud VPS → App Catalog → Docker (rekomendasi: 2 vCPU / 4 GB RAM, buka port 8000 dan 7860 di Firewall IDCloudHost), lalu jalankan perintah ini di Terminal SSH:
          
    
          
    # 1. Clone repo & masuk ke folder tradeflow-sentinel
git clone <URL_REPO_GITHUB_ANDA>
cd Hacktiv8---IBM-National-Hackathon/tradeflow-sentinel
cp .env.example .env

# 2. Generate Secret Key & matikan blokir SSRF internal untuk Linux VPS
SECRET_KEY=$(python3 -c "import base64,secrets; print(base64.urlsafe_b64encode(secrets.token_bytes(32)).decode())")
sed -i "s|<your-langflow-password>|TradeFlow2026!|g" .env
sed -i "s|<run-command-above-to-generate>|${SECRET_KEY}|g" .env
sed -i "s|LANGFLOW_SSRF_PROTECTION_ENABLED=true|LANGFLOW_SSRF_PROTECTION_ENABLED=false|g" .env

# 3. Penting di Linux VPS: arahkan host.docker.internal ke container FastAPI
sed -i "s|http://host.docker.internal:8000|http://tradeflow_sentinel_api:8000|g" "TradeFlow Sentinel Compliance Tool.json"

# 4. Jalankan kedua container di background
docker compose up -d --build

    2. Pasang Web UI Portable Ini di langflow_sentinel_engine.py
    
            
          
    
          
    
            Simpan file HTML ini sebagai tradeflow-sentinel/tradeflow_sentinel_portable_ui.html, lalu tambahkan 10 baris berikut di bawah app = FastAPI(...) pada langflow_sentinel_engine.py agar halaman ini tampil otomatis saat orang membuka http://IP-VPS:8000/ dari HP/Laptop:
          
    
          
    from fastapi.middleware.cors import CORSMiddleware
from fastapi.responses import HTMLResponse

app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_methods=["*"],
    allow_headers=["*"],
)

@app.get("/", response_class=HTMLResponse, include_in_schema=False)
async def serve_portable_ui():
    ui_file = Path(__file__).parent / "tradeflow_sentinel_portable_ui.html"
    if ui_file.exists():
        return HTMLResponse(ui_file.read_text(encoding="utf-8"))
    return HTMLResponse("<h3>TradeFlow Sentinel Active. Open <a href='/docs'>/docs</a></h3>")
    
        
    

      
    

      
      
    
        
    3. Cara Kerja Integrasi AI / LLM Tanpa Membuka Aplikasi Desktop IBM Bob
    
        
    
          Aplikasi desktop IBM Bob pada dasarnya hanyalah Agentic Client yang membaca aturan di tradeflow-sentinel/AGENT.md dan memanggil tool MCP di Langflow. Saat di-deploy ke IDCloudHost, kecerdasan AI dan format laporan ala IBM Bob tetap berjalan penuh di server melalui 3 opsi konfigurasi di langflow_sentinel_engine.py:
        
    
        
    
          
    
            
    Opsi A · AGENT.md Persona + Mock Cache (Default: USE_MOCK_LLM=true)
    
            
    
              Menggunakan konstitusi AGENT.md Bagian 5 & 6 (Passthrough Numerical Faithfulness) langsung di kode tanpa memotong kuota token IBM watsonx (0 Bobcoins / < 2 ms). Cocok untuk ratusan responden validasi praktisi.
            
    
          
    
          
    
            
    Opsi B · Live IBM watsonx.ai Granite 3.3 8B (USE_MOCK_LLM=false)
    
            
    
              Fungsi _live_synthesis() di baris 475 langflow_sentinel_engine.py memanggil langsung model ibm/granite-3-3-8b-instruct (temperature=0.0) di cloud IBM watsonx.ai, lalu diverifikasi oleh Guardrail 2.
            
    
          
    
          
    
            
    Opsi C · Langflow 9-Node REST API (POST :7860/api/v1/run/...)
    
            
    
              Web UI menembak langsung API container IBM Langflow (:7860) yang menjalankan 3 node paralel Intent & Payload Extractor → ⚖️ Sentinel Compliance Checker → 📋 Report Formatter.

    🔍 Verifikasi Langsung 4 Titik Kode Temuan Mentor Teknis (Section 2 – Technical Feedback)
    
          
    
            
    
              1. Edge-Case #1 (Huruf Kapital `"HIMBARA"`):
              
    Kode lama memakai "Himbara" not in bank_cat (case-sensitive). Kini diperbaiki dengan bank_cat.upper() sehingga "HIMBARA" lolos mulus sebagai COMPLIANT (True Negative) tanpa false alarm.
    
            
    
            
    
              2. Edge-Case #2 (IMO di Luar File / KeyError Guard):
              
    Menguji IMO 9999997 yang tidak ada di database. Tidak memicu KeyError, melainkan ditolak secara aman (FAIL-CLOSED: IMO tidak terdaftar di registri AISHub).
    
            
    
            
    
              3. Edge-Case #3 (Benchmark Tak Dikenal / ZeroDivisionError Guard):
              
    Menguji HS Code 9999.99 (harga benchmark 0 / tak dikenal). Tidak memicu ZeroDivisionError, melainkan FAIL-CLOSED: Wajib verifikasi harga manual.
    
            
    
            
    
              4. Edge-Case #4 (Kapal Tanpa lat/lon / Anti Fail-Open):
              
    Menguji kapal dengan koordinat lat=null, lon=null. Tidak lagi diberi jarak 0 NM lalu lolos, melainkan FAIL-CLOSED: AIS Dark Vessel / Koordinat Hilang.
